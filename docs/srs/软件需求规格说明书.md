### 1.2 系统概述

DanmakuStream 是一个面向创作者社区的弹幕视频点播 + 实时直播一体化平台。系统的一般特性包括：

- **视频点播链路**：支持游客和注册用户浏览、搜索、播放公开视频，支持弹幕、评论、点赞、收藏、观看历史、稍后再看等完整互动。
- **创作者生态**：支持创作者身份的用户投稿视频、上传封面、跟踪审核与转码状态，并开放会员方案订阅、作品数据与粉丝趋势分析。
- **内容治理链路**：审核员审核视频与弹幕；管理员调整用户角色、配置首页横幅与公告、检查存储/流量/CPU/在线人数等基础设施指标。
- **直播链路**：主播通过 SRS（RTMP→HLS）推流发布直播，观众进入直播间接收实时弹幕、礼物、点赞、Super Chat，主播端查看在线人数与互动统计。
- **社交与通知**：用户间可建立关注关系、分组、特别关注、屏蔽；支持用户私信（文字/图片/短视频/平台视频分享）与内容通知。
- **资料库**：登录用户的观看历史、播放进度、稍后再看、点赞、收藏、关注分组等个人记录以服务端为准，跨设备一致。
- **部署与演进**：当前交付形态为 Docker Compose 单体；同时完成 Kubernetes 改造设计，支持后续平滑演进为微服务与多副本高可用部署。

## 3 需求

本章分条描述 DanmakuStream CSCI 的需求，即构成 CSCI 验收条件的特性。给每个需求指定项目唯一标识符（REQxx / UCxx / INT-TCxxx 等）以支持测试和可追踪性。

### 3.1 所需的状态和方式

DanmakuStream CSCI 定义以下 4 种运行状态，每种状态的能力集合不同：

| 状态 | 名称 | 进入条件 | 可见能力 | 典型能力约束 |
|---|---|---|---|---|
| S1 | 正常运行 | 前后端容器健康、MySQL 可连接、SRS（如需）可用、存储目录可写 | UC01～UC13 全部能力允许，仅按角色鉴权裁剪 | 视频状态机不得跳过终态保护；所有写操作通过 JWT 鉴权与权限中间件 |
| S2 | 降级运行（媒体不可用） | 后端 + DB 正常，但 SRS 或本地视频存储异常 | UC01/07/08/11/12/13/14 保持可用；UC02/03/04/05/06/09/10 涉及媒体播放/上传时返回"媒体服务暂不可用" | 不得把"媒体缺失"的视频错误标记为 `approved`；实时互动 WS 链路保持可用，弹幕走 Hub 内存态 |
| S3 | 降级运行（实时链路不可用） | 后端 HTTP 正常，但 WS 端口 / Gorilla 会话异常 | UC01/02/03/04/06/07/08/09/11/12/13/14 HTTP 能力保持；UC05 弹幕、UC10 实时互动、UC11 实时私信降级为轮询或离线消息 | 在线人数统计不重复计；轮询周期 ≥ 10s 不得对 DB 产生过高 QPS |
| S4 | 维护模式（只读） | 运维通过配置显式开启 `maintenance.read_only=true` | 仅 UC01（登录/读资料）、UC02（浏览/搜索/只读播放）、UC12（只读统计）、UC13（只读运维视图）允许 | 所有 POST/PUT/DELETE 返回 503 + `maintenance in progress`；不得写入 DB / 上传文件 |

### 3.2 需求概述

#### 3.2.1 目标

1. **开发意图**：构建一个功能完整、可追溯、可演示的弹幕视频 + 直播平台，满足 2026 夏季软件工程综合实践课程 13 个用例的验收要求，并支持从单体到 Kubernetes 的部署演进。

2. **现有问题 / 要解决的问题**：
   - 课程样例多为 CRUD demo，缺少"视频状态机 + 直播媒体链路 + 实时弹幕 + 个人资料库跨设备一致性"这一复杂度组合。
   - 团队协作下经常出现"图/码/测试/文档不同步"的追溯缺口，需建立从需求到代码到测试的双向追踪矩阵。
   - 初始 Docker Compose 形态缺乏扩容与高可用说明，需交付 K8s 改造设计与验收清单。

3. **主要功能与流程**：见图档 [USECASE-OVERVIEW.puml](models/usecase/USECASE-OVERVIEW.puml)。核心数据流程：

   - 视频流：投稿 → 上传 → 转码 → 审核 → 公开列表 → 播放 + 互动 + 统计。
   - 直播流：预约 → 推流 → SRS 转 HLS → 观众拉流 + 实时互动 → 下播归档。
   - 用户流：注册 → 登录 → 鉴权 → 关注 / 会员 / 私信 / 资料库。
   - 治理流：审核员审核内容 → 管理员配运营信息 → 运维看板 → K8s 扩缩容。

4. **系统高层次图**：
   - 总体组件图：[COMPONENT-OVERVIEW.puml](models/component/COMPONENT-OVERVIEW.puml)。
   - 概念类图：[CLASS-B.puml](models/class/CLASS-B.puml)。
   - 部署图（单体 / K8s）：见 [REF-11] 与 §3.11。

DanmakuStream 既可以作为独立产品交付（Docker Compose），也可以是更大体系（"课程学生作品集合平台"）的一个组成部分，此时它通过 Nginx Ingress / API 网关对外暴露 `/api/v1/*`、`/ws/*`、`/live/*` 三类前缀。

#### 3.2.3 用户的特点

系统定义 6 类用户：

| 角色 | 使用频率 | 典型操作 | 能力 / 限制 |
|---|---|---|---|
| 游客 | 偶尔 | 浏览首页、搜索、播放公开视频 | 不允许写任何用户数据；不得访问受保护接口 |
| 普通用户（user） | 日常 | 登录、维护资料、互动、资料库、关注、预约、私信 | 拥有个人 `user_id`；鉴权后可写 |
| 创作者（creator） | 中高频 | 投稿、看创作分析、配置会员方案 | user 权限 + 创作中心页面 |
| 主播（streamer） | 中高频 | 开播、下播、看直播实时数据 | user 权限 + 直播间推流授权 |
| 审核员（moderator） | 低频 | 审核视频、屏蔽弹幕 | 不能调整 admin 权限、不能改运营横幅 |
| 管理员（admin） | 低频 | 调整用户角色、运营配置、基建视图 | 全局最高权限；所有 admin 接口必须带审计日志 |

用户能力假设：
- 熟悉 Web 表单与视频播放操作；
- 投稿与直播功能需要具备基础的 OBS / FFmpeg 使用能力（系统提供推流地址与密钥提示）。

#### 3.2.4 关键点

| 类型 | 关键项 |
|---|---|
| 关键功能 | 视频状态机（draft→processing→pending→approved/rejected/removed）终态保护；直播推流 → HLS 播放链路；弹幕/聊天双 Hub；资料库 `(user_id,video_id)` 唯一约束；RBAC 四级权限（user/creator/moderator/admin） |

### 3.3 需求规格

#### 3.3.1 软件系统总体功能 / 对象结构

总体功能划分为 6 大域，对应 6 条 Nginx upstream 前缀（为未来微服务化拆分预留）：

| 域 | API 前缀 | 包含的 UC | 代码主要模块 |
|---|---|---|---|
| D1 认证与用户域 | `/api/v1/auth`、`/api/v1/user` | UC01、UC06、UC07、UC11、UC12 账户侧 | `auth/*`、`user/*`、`message/*`、`creator/*` |
| D2 视频域 | `/api/v1/videos`、`/api/v1/media`、`/api/v1/collection` | UC02、UC03、UC04、UC05（点赞/收藏）、UC06（历史/进度/稍后再看） | `video/*`、`media/*`、`collection/*`、`danmaku/*`、`comment/*` |
| D3 直播域 | `/api/v1/live`、`/ws/live` | UC09、UC10 | `live/*`、`ws/live_publish_handler.go`、`logic/chat/hub.go` |
| D4 关系与通知域 | `/api/v1/user`（关系子路由）、`/api/v1/notifications` | UC07、（UC08/UC11 通知派生） | `user/relationship_handler.go`、`notification/*` |
| D5 会员域 | `/api/v1/membership` | UC08 | `membership/*` |

#### 3.3.3 描述约定

- **时间**：全部按 UTC+8 存 `datetime`（GORM `time.Local = Asia/Shanghai`），对外展示格式 `YYYY-MM-DD HH:mm:ss`。
- **容量 / 大小**：统一采用十进制字节（B / KB / MB / GB）；1 GB = 1,000,000,000 B。
- **ID 编号**：MySQL `BIGINT UNSIGNED AUTO_INCREMENT`；对外 JSON 用数字字符串，避免 JS precision loss。
- **货币与周期**：会员价格以"分 / 月"为单位（整数，避免浮点误差）。
- **API 一致响应**：`{ code: 0, message: "ok", data: {.../[]} }`，非 0 code 为业务错误。
- **数学符号**：求和 `Σ`、按日聚合 `GROUP BY DATE(created_at)`。排序限定：`sort` 白名单 `{hot,newest,oldest,views,likes}`；不在白名单时返回默认 `newest`，不得抛出 500。

### 3.4 CSCI 能力需求

以下每条能力给出"输入 / 处理 / 输出"三要素，并给出项目唯一标识符（REQxx / UCxx）支持追踪。异常与越权行为的处理均嵌入"处理"环节，不再逐条重述（所有写操作默认必须鉴权）。

#### 3.4.1 UC01 用户注册、登录与资料维护（REQ01）

| 子项 | 内容 |
|---|---|
| **前置条件** | 系统可用 MySQL；JWT 密钥已配置 |
| **状态关联** | S1/S2/S3 全量允许；S4 仅只读登录 / 只读资料 |
| **输入（I）** | I1 注册：`{ nickname, password }`（nickname 2–20 字，密码 ≥ 8 位且含字母数字）<br>I2 登录：`{ nickname, password }`<br>I3 修改资料：`{ nickname?, avatar_url?, bio? }`（JWT `Authorization: Bearer <token>`） |
| **处理（P）** | P1 注册：昵称唯一查询 → bcrypt 哈希密码 → 写 `users`（role=user） → 返回空 data + 隐含可登录状态。重复昵称返回 `409 Conflict { code:1001 }`。<br>P2 登录：bcrypt 校验 → 签发 JWT（含 `user_id`、`role`、过期时间 AccessExpire） → 失败返回 `401 { code:1002 }`，不区分"用户不存在/密码错误"以避免枚举。<br>P3 修改资料：校验 JWT 合法性与未过期 → 检查新昵称唯一（非自身） → 更新 `users`；非法头像 URL/超长 bio 返回 `400 { code:1003 }`。<br>P4 越权：未登录访问 P3 或 P4 他人资料写接口 → `401` |
| **输出（O）** | O1 注册成功：`200 { code:0 }`；失败：`400/409` + 业务 code。<br>O2 登录成功：`200 { accessToken, expiresIn, user:{ id,nickname,avatar,role } }`。<br>O3 修改成功：`200 { code:0, data:{ id,nickname,avatar,bio } }`；刷新与重新登录后读取值一致。<br>O4 `/api/v1/auth/me`：从 JWT 还原当前用户信息，用于前端路由守卫。 |
| **时限约束** | 注册 / 登录 P95 ≤ 300ms；资料修改 P95 ≤ 200ms（不含对象存储上传）。 |

#### 3.4.3 UC03 创作者投稿与状态跟踪（REQ03）

| 子项 | 内容 |
|---|---|
| **前置条件** | 调用方 `role ∈ {creator, admin}`，已登录；上传目录可写 |

#### 3.5.2 EXT-01 用户接口（浏览器交互）

- **类型**：用户接口（Web UI）。
- **屏幕约定**：桌面 ≥ 1280×720；移动端 ≥ 375px 宽。
- **公共交互组件**：顶部导航栏（游客/登录态不同）、搜索框、播放器（含弹幕层）、表单校验反馈（非 500，使用 code→message 映射）。
- **异常提示**：统一使用 Element Plus `ElMessage`，成功绿色、失败红色；网络失败 3s 后允许手动重试按钮。
- **无障碍（最低限度）**：关键按钮必须有 aria-label；表单输入必须有可见 label 或 placeholder。

#### 3.5.3 EXT-02 数据库接口（MySQL）

- **类型**：软件接口（GORM driver）。
- **DSN 格式**：`user:pass@tcp(host:3306)/dbname?charset=utf8mb4&parseTime=True&loc=Local`，支持 TLS（生产必开）。
- **连接池**：`SetMaxOpenConns=100, SetMaxIdleConns=20, ConnMaxLifetime=1h`。
- **事务**：审核、扣减、批量全已读等强一致场景必须 `BEGIN / COMMIT / ROLLBACK`。
- **唯一约束**（不可缺失）：
  - `users.nickname UNIQUE`
  - `watch_histories(user_id,video_id) UNIQUE`
  - `watch_laters(user_id,video_id) UNIQUE`
  - `follows(follower_id,followee_id) UNIQUE`
  - `subscriptions(user_id,plan_id) UNIQUE`
  - `live_schedule_reservations(user_id,schedule_id) UNIQUE`
- **备份/恢复**：每日 `mysqldump`（生产必须）；CI 测试数据库每次 job 隔离（3306 service）。

其余 3.5.x（EXT-03～EXT-08 单接口条目）遵循以下通用约束，具体字段级规格在 API 代码注释与 OpenAPI（未来可由 Gin Swagger 生成）中定义，本 SRS 不重复展开：

- **数据元素级要求**：所有主键 BIGINT UNSIGNED；时间 DATETIME(3)；文本类字段设置合理上限（昵称 20、弹幕 60、评论 500、公告 2000、私信 2000）。
- **保密性约束**：`password` 字段 bcrypt 存储；Secret 类（JWT、SRS、MySQL root）仅从环境变量 / Secret 读，不得出现在日志或错误堆栈。
- **协议级要求**：EXT-06 WS 消息必须有 `ping/pong` 心跳（30s 间隔，120s 无 pong 断连）；EXT-04 RTMP 使用 `?sign=` 查询参数鉴权（SRS `http-callback` 校验）。

### 3.6 CSCI 内部接口需求

当前交付形态为单体。CSCI 内部模块接口（handler → logic → repo → model）全部由 Go 接口类型（`interface`）显式声明并在 `wire` / 手动依赖注入中绑定，**不允许跨模块直接 import 私有实现细节**。约束如下：

- 所有 handler 不得直接 import `gorm.DB`；必须通过 `logic.XxxLogic` / `repo.XxxRepo` 层访问。
- handler 层不允许写业务规则（如终态保护、幂等、价格校验），业务规则必须在 logic 层且由单元测试覆盖。
- 实时层（danmaku hub、chat hub、live publish）与 HTTP handler 的交互通过 channel / Pub（内存）；持久化落盘由 hub 异步写 repo，不得阻塞 WS 帧处理。
- 未来拆分微服务时，本条目约束保证 `logic/repo` 包可直接抽为独立 service 模块。

### 3.7 CSCI 内部数据需求

除了 §3.5.3 中列举的带 UNIQUE 约束的业务表，CSCI 内部还需要以下数据表 / 内存态 / 本地缓存：

- **持久化表**：`users, videos, video_media, danmakus, comments, watch_histories, watch_progresses, watch_laters, collections, collection_items, follows, follow_groups, blocks, notifications, membership_plans, orders, subscriptions, live_rooms, live_broadcasts, live_schedules, live_schedule_reservations, live_danmakus, live_gifts, messages, conversations, daily_creator_stats, banners, announcements, audit_logs, uploaded_media` 等（以 `backend/internal/model/mysql/models.go` 为准）。
- **内存态**：danmaku hub（房间→订阅者）、chat hub（会话→订阅者）、WS 连接计数器、最近 10min 点赞计数缓存。
- **本地缓存**：10s 热门视频统计缓存（写穿透 + 过期回源）。

若未来有性能需求，可将内存态改为 Redis（属于实现细节变更，不影响本 SRS 验收）。

### 3.9 安全性需求

本 CSCI 不涉及人员/财产/环境物理安全（非工业控制系统）。对应"把潜在危险降到最低"的软件安全措施包括：

- **CSCI 级防误操作**：视频终态保护（§3.4.4 P2）、直播结束必须房主或 admin、会员支付幂等、批量清空操作只能操作当前用户的数据。
- **CSCI 级防无效操作**：所有写操作接口的参数校验（白名单 sort、MIME、大小、时间范围、角色枚举）通过才进入 logic 层；非法输入在 handler 入口失败，不会触发后续无效数据库写入或文件写入。
- **CSCI 级上传安全**：媒体上传仅允许 MIME 白名单；文件扩展名与真实 MIME（`http.DetectContentType`）双校验；上传目录禁止脚本执行权限（生产 Nginx 配置 `location ^~ /media/ { types {} default_type application/octet-stream; }`）。

### 3.10 保密性和私密性需求

- **环境**：开发 / CI 使用公开 GitHub Actions Runner + 随机弱密码；生产环境必须使用独立 VPC + Secret 注入，MySQL 不得暴露公网。
- **类型和程度**：JWT、用户 bcrypt 密码哈希、私信内容、会员订单、审计日志、管理员操作均为私密数据；私信附件仅允许发送者/接收者双方访问（URL 中 `?token=` HMAC 校验）。
- **保密性策略**：遵循最小权限；DB 账号按服务拆分（只读、读写、管理）；审计日志至少保留 180 天。

### 3.14 设计和实现的约束

- **体系结构约束**：必须能在单体（4 容器）形态跑通；同时交付 K8s 拆分设计（§3.11 / §3.4.13）。数据库/媒体/实时层接口按可拆分方式设计。
- **标准 / 规范**：
  - Go：遵循 gofmt、go vet；不得使用 `interface{}` 做类型断言传递请求上下文。
  - Vue/TS：`vue-tsc --noEmit` 必须零错误；store 使用 Pinia action，不得直接跨组件 mutate store。
  - SQL：GORM AutoMigrate 仅开发环境；生产必须通过 migration 脚本管理。
  - API 命名：`/api/v1/<domain>/<resource>`；`POST /me/...` 从 JWT 取 user_id，不得从 query 取。
- **灵活性 / 可扩展性**：为角色系统保留枚举扩展位；为实时层保留 Redis Pub/Sub 替换内存 hub 的接口；为推荐系统预留 `/api/v1/recommendations` 路径（离线脚本输出）。

### 3.15 数据

- **输入数据量**：单笔投稿 ≤ 2GB（视频）+ ≤ 10MB（封面）；单笔评论 / 私信 / 公告长度见 §3.7。
- **输出数据量**：列表分页默认 `pageSize=20`，允许 `1 ≤ pageSize ≤ 100`；超过 100 强制 100 防拉爆。
- **数据管理能力**：MySQL 表级增量 + 每日全量备份；媒体文件按 `YYYY/MM/DD/{video_id}/...` 分目录，方便冷备与回收。

### 3.16 操作

- **常规操作**：用户常规 UI 操作（登录、浏览、投稿、互动、直播、私信、订阅、分析、后台）均通过浏览器。
- **特殊操作**：
  - 主播开播：需要 OBS 配置"服务器=RTMP 地址 + 串流密钥=playKey?sign=xxx"（系统在工作台给出复制按钮）。
  - 维护模式 S4：运维通过环境变量 `MAINTENANCE_READ_ONLY=true` 重启 backend；或 K8s `kubectl set env deploy/backend MAINTENANCE_READ_ONLY=true`（滚动更新）。
- **初始化操作**：
  - 首次部署：执行 `DB 初始化 SQL`（建库 + 建表 + 插入 admin 种子账号 admin/admin123 后强制改密钩子）。
  - CI 初始化：service mysql 中 `MYSQL_DATABASE=danmakustream`，测试启动时由 `TestMain`（或集成测试入口）执行 AutoMigrate。
- **恢复操作**：
  - 媒体文件丢失：从备份还原目录；DB 中的 `media.status` 扫描修复脚本（可由运维 Job 单独执行，标记 failed）。
  - DB 损坏：从 mysqldump 还原，媒体文件回放至同一时间点，视频状态机由 approved 回滚到 processing（通过 audit_logs 审计）。

### 3.17 故障处理

| 类别 | 属于软件系统的问题 | 错误信息 | 补救措施 |
|---|---|---|---|
| 数据库连接丢失 | 是（CSCI 可用性保障） | 503 `{code: 9001, message:"db unavailable"}` | 指数退避重试 3 次；进入维护模式对外只读 |
| JWT 失效 / 篡改 | 是（安全） | 401 `{code:1004}` | 前端跳登录，刷新 token 为增强项 |
| 上传文件超限 / 非法 MIME | 是（输入校验） | 413 / 400 `{code:3001/3002}` | 前端表单显式报错；文件不写盘 |
| 视频状态机非法流转 | 是（业务保护） | 409 `{code:4002,"final state protected"}` | 拒绝写入，并记录 audit_logs with incident_id |
| 推流密钥错误 / 非房主 | 是（直播安全） | SRS http-callback 返回 403，SRS 拒绝流 | 主播端展示"推流失败"，不更新 live 状态 |
| WebSocket 心跳超时 | 是（实时链路） | 浏览器 close code 1008 | 前端指数退避重连；后端 counter 正确去重 |
| 媒体文件播放失败（HLS 404） | 否 / 部分：CSCI 需显式降级 | 播放器展示"媒体服务暂不可用"+ 重试按钮 | 进入 S2 降级；视频不得错误标为 approved |
| 磁盘空间不足（< 5%） | 是（CSCI 基建监控） | UC13 metrics storage_pct 告警；admin 看板标红 | 关闭上传接口；告警运维；worker 停止写 history 行以免 DB 与实际文件不同步 |

### 3.18 算法说明

| 算法 | 概况 | 公式/逻辑 |
|---|---|---|
| A1 按日数据分析聚合 | 为创作者统计按日的 views / likes / comments / newFollowers / videosPublished | `daily_creator_stats(date,creator_id)= GROUP BY DATE(created_at)` 按明细表聚合；缺失日填 0；排行榜 TOP N 用 `ORDER BY metric DESC LIMIT N` |
| A2 弹幕时间轴排序 | 进入视频详情页弹幕按 `time_ms` 升序 | `ORDER BY time_ms ASC, created_at ASC` |
| A3 播放进度合并 | 心跳 15s 去抖 + ended 强制覆盖 | `ON DUPLICATE KEY UPDATE progress=IF(event='ended',progressSec,GREATEST(progress,progressSec))` |
| A4 关注/点赞/收藏幂等 | UNIQUE 约束 + `affected_rows` 检查 | INSERT 冲突时 affected_rows=0 则计数器不 +1；DELETE WHERE 条件带 user_id 防重复 -1 |
| A5 会员到期日计算 | 下单月份 × 30 天 简化（或使用 SQL `DATE_ADD(now, INTERVAL months MONTH)`） | `valid_until = COALESCE(当前订阅有效日, now) + INTERVAL months MONTH` |
| A6 ItemCF 离线推荐（加分项） | 用户-视频交互矩阵（观看 > 30% + 点赞 + 收藏加权），计算物品相似度 TopK | `sim(i,j)=|U_i ∩ U_j| / sqrt(|U_i|*|U_j|)`；推荐分 `rec(u,i)=Σ_{j∈R_u} w(u,j)·sim(i,j)` |

## 7 注解

### 7.1 术语表

| 术语 | 定义 |
|---|---|
| CSCI | 计算机软件配置项（Computer Software Configuration Item）。本 SRS 中 DanmakuStream 整体作为一个 CSCI。 |
| 创作者（Creator） | 已获得 `role=creator` 身份的普通用户，可投稿视频、查看创作分析、配置会员方案。 |
| 主播（Streamer） | 已开通直播间、拥有推流权限的用户；通常 `role=creator` 或以上。 |
| 审核员（Moderator） | `role=moderator`，可以审核视频与屏蔽弹幕，但不能调整 admin 权限或修改运营横幅。 |
| 管理员（Admin） | `role=admin`，平台最高权限，可调整角色、配置运营、查看基建指标。 |
| 视频状态机 | Video.status 从 draft → processing → pending → approved/rejected/removed 的有限状态转换，终态不可覆盖。 |
| 弹幕 / Danmaku | 在视频播放时间轴上按 time_ms 定位展示的滚动字幕。 |
| SRS | Simple Realtime Server，开源媒体服务器；本项目用其完成 RTMP 推流 → HLS 分发的转换。 |
| HLS | HTTP Live Streaming，由 m3u8 主清单 + 多个 .ts 分片组成的 HTTP 协议直播方式。 |
| RTMP | Real-Time Messaging Protocol，主播推流使用的协议，使用 TCP 1935 端口。 |
| 稍后再看 / Watch Later | 用户在浏览时将视频加入"稍后再看"队列，系统在个人资料库中持久化保存。 |
| 会员订阅 / Membership | 创作者配置价格方案，用户购买后在有效期内获得会员内容访问 / 特别关注 / 身份标识等权益。 |
| 三层顺序图 | 系统级（SYS-SEQxx） / 组件级（COMP-SEQxx） / 对象级（OBJ-SEQxx）共 3 组 × 13UC = 39 张。 |
| 追溯率 | 需求条目映射到代码+测试的覆盖率；目标 100%。 |
| 演示支付 Demo Pay | 课程场景无真实支付渠道，使用 `POST .../demo-pay` + nonce 校验模拟支付成功回调。 |
| 降级运行 | §3.1 的 S2/S3/S4 状态：非关键能力受限时保证核心 HTTP / DB 路径可用并显式提示。 |
| 弹幕 Hub / Chat Hub | 基于 Gorilla WebSocket 的内存态发布订阅组件，按房间 / 会话广播消息。 |
| ItemCF | 基于物品的协同过滤（Item-based Collaborative Filtering），本项目用于离线推荐加分演示。 |
