## 3. 结论摘要（答辩稿要点）

1. **吞吐差异**：BM01 单体 vs 微服务为 88.48:89.79 req/s；BM03 微服务高 1.80%。固定 VUS 且包含 think time，吞吐差异整体较小。
2. **延迟差异**：BM02 微服务 Avg 52.00ms，单体 P95 74.72ms 更高；本机同网络条件下，拆分后的 user-service 路径没有表现出额外网络开销，结果也可能受两套实现及数据库状态差异影响，不能仅归因于架构。
3. **资源占用差异**：单体 backend vs 三个微服务 Go 进程总 RSS 为 15.30MB vs 48.49MB（多 33.19MB，约 +216.93%）；微服务以更高常驻内存换取独立部署与扩容能力。
4. **可扩展性启示**：微服务可单独扩容 user-service（登录热点）和 engagement-service（资料库/直播热点）；但本轮两套架构均为固定单副本，只能证明当前单副本性能，不能作为线性扩展或 HPA 收益的证据。扩缩容收益需另做固定副本与 HPA 的阶梯负载对照实验。
5. **稳定性**：18 个正式场景轮次的业务请求错误率均为 0%，低于 2% 阈值，符合验收门槛。
