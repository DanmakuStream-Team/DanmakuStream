## 1 引言

### 1.1 目标

本报告用于说明 DanmakuStream 单体版本的测试范围、测试方法、执行环境、测试用例、执行规程和实际结果，确认 UC01～UC13 的主要成功流程、异常流程、权限边界、数据一致性和浏览器端业务闭环是否满足验收要求，并为后续微服务版本提供可比较的质量基线。

### 1.2 背景

DanmakuStream 是一个包含视频点播、弹幕评论、用户关系、会员订阅、直播互动、私信、创作者分析和平台管理能力的视频社区系统。系统采用 Vue 3 前端、Go/Gin 后端、MySQL 数据库和 SRS 流媒体服务，并提供 Docker Compose、Kubernetes 清单及 GitHub Actions 流水线。

测试的主要原因如下：

1. 业务范围包含 13 个相互关联的用例，接口、数据库和页面状态需要保持一致。
2. 系统涉及鉴权、角色权限、订单幂等、WebSocket、媒体文件和直播状态等高风险路径。
3. 课程要求单元、API/集成和 E2E 三层测试齐全，且任一测试失败必须阻断镜像构建与部署。
4. 当前单体版本将作为后续微服务拆分的对照基线，需要保留可重复执行的测试方法和原始证据。

### 1.3 范围

本报告覆盖：

- UC01～UC13 的功能和异常流程；
- Go 后端单元测试、真实 MySQL 集成测试和 HTTP API 测试；
- Vue 前端类型检查、生产构建和 Playwright Chromium E2E；
- JWT 鉴权及 user、moderator、admin 权限边界；
- RTMP—SRS—HLS 媒体链路、WebSocket 实时消息及断线恢复；
- CI 测试失败阻断镜像构建的红灯/绿灯验证。

本报告不覆盖后续微服务版本、HPA 扩缩容实验、单体/微服务性能对比、长时间稳定性、专业渗透测试和多浏览器兼容性测试。这些内容应在对应阶段形成独立报告。

### 2.3 测试方法

1. **单元测试**：使用 Go `testing`、`httptest` 和表驱动测试验证纯逻辑、参数边界、中间件及 Handler 错误分支。
2. **API/集成测试**：使用临时 MySQL 数据库或独立测试数据，通过 Go 集成测试及 Shell/curl 调用真实 HTTP 接口，同时断言响应和数据库结果。
3. **E2E 测试**：使用 Playwright Chromium 操作真实 Vue 页面，验证登录、页面交互、刷新持久化、路由权限和跨用户业务流程。
4. **媒体与实时链路**：使用 FFmpeg、SRS、HTTP/HLS 和 WebSocket 验证推流、播放、断流恢复、实时消息及在线人数。
5. **CI 门禁**：GitHub Actions 并行执行后端测试和前端构建，下游 API/E2E 全部通过后才允许构建版本镜像；通过故意失败测试验证阻断规则。
6. **追溯方法**：使用 [总追溯表](../traceability/master.md)连接 REQ、UC、三层模型、代码模块、测试编号和结果。

### 2.4 测试通过准则

- 单元、API/集成及 E2E 命令退出码必须为 0；不得以日志中出现部分成功代替整体成功。
- HTTP 状态码、响应字段、数据库结果和页面状态必须与测试用例预期一致。
- 未授权操作不得写入数据；事务失败不得返回成功或留下部分更新。
- E2E 操作刷新后，关键状态必须保持；失败时保存 trace、截图或视频。
- CI 中任一必需测试失败，`docker-build` 和后续部署必须为 skipped 或未执行。
- 测试结果必须能追溯到仓库报告、原始输出或 GitHub Actions 运行，不允许把未执行项填写为通过。

## 3 测试设计说明

### 3.1 目的

本节将总体测试计划细化为可执行的测试层次、输入组合、断言方式和特征通过标准，确保每个用例至少具有单元、API/集成和 E2E 证据。

### 3.2 详细说明

#### 3.2.1 测试设计说明标识符

`DMS-TD-UC01-13-20260829`，关联测试计划 `DMS-TP-MONO-20260829`。

#### 3.2.2 要测试的特征

测试设计围绕以下特征组合展开：

- 正常输入与边界/非法输入；
- 未登录、普通用户、审核员和管理员权限组合；
- 首次操作、重复操作、取消操作及并发/重试幂等；
- 数据库成功、资源不存在、媒体不可用及持久化失败；
- 页面首次进入、操作后刷新、断线重连和跨用户状态同步；
- 单机业务运行与 CI 自动化质量门禁。

#### 3.2.3 方法细化

- 输入等价类包括合法值、空值、越界值、错误格式、无效 ID、重复请求和越权身份。
- 状态类业务至少覆盖创建前、处理中、成功终态、失败终态和取消状态。
- 数据库写操作同时检查 API 响应与实际表记录，软删除业务还检查列表过滤结果。
- E2E 使用固定测试账号和带时间戳/用例前缀的数据，执行前准备、执行后清理。
- WebSocket 和直播测试检查事件内容、连接恢复、人数去重及持久化失败是否正确传播。
- 测试报告以退出码和原始输出为准；浏览器失败使用 Playwright trace、截图和视频分析。

#### 3.2.4 特征通过准则

某业务特征仅在以下条件同时满足时判定通过：

1. 对应自动化测试执行成功且无未解释的 skip；
2. 关键异常路径有明确错误状态，且不产生脏数据；
3. 页面、接口与数据库结果一致；
4. 测试结果能映射到需求和用例编号；
5. 回归测试未破坏其他已通过用例。

## 5 测试规程说明

### 5.1 目的

本规程用于统一测试准备、执行、证据保存、清理和异常处理步骤，使测试可以由其他成员或教师复验。

### 5.2 详细说明

#### 5.2.1 测试规程说明标识符

`DMS-TPROC-MONO-20260829`

#### 5.2.2 特殊要求

- MySQL 集成测试通过 `DANMAKU_TEST_ADMIN_DSN` 指定测试管理员连接，不得使用生产数据库。
- HTTP API 和 E2E 测试需要后端健康检查通过，并提供 `VIDEO_DIR`、`MYSQL_CMD` 等测试环境变量。
- Playwright 首次执行前需要安装 Chromium；失败证据不得在问题定位前删除。
- 媒体链路测试需要 FFmpeg 和 SRS，端口不得与其他实例冲突。
- 测试脚本必须以非零退出码报告失败；使用 `tee` 时必须启用 `set -o pipefail`。

#### 5.2.3 规程步骤

1. 检出目标提交，确认工作区和测试版本。
2. 启动 MySQL/SRS 或准备等效隔离环境，执行健康检查。
3. 在 `backend/` 执行 `go test -count=1 ./...`。
4. 设置测试 DSN，执行带 `integration` 标签的 Go 集成测试。
5. 启动单一后端实例，依次运行 `tests/api/run-all.sh` 中的 API 套件。
6. 在 `frontend/` 执行 `npm ci`、安装 Chromium、运行 `npm run build` 和 `npm run test:e2e`。
7. 检查退出码、测试汇总、数据库结果和 Playwright HTML/trace。
8. 保存原始输出到 `docs/testing/reports/` 或 CI artifact，并更新总追溯表。
9. 清理临时账号、数据库、媒体目录和测试进程。
10. 若出现失败，记录现象、定位原因、提交修复并执行相同范围回归。

常用命令：

```bash
(cd backend && go test -count=1 ./...)

export DANMAKU_TEST_ADMIN_DSN='root:password@tcp(127.0.0.1:3306)/danmakustream?charset=utf8mb4&parseTime=True&loc=Local'
(cd backend && go test -count=1 -tags=integration ./internal/handler/v1/live ./internal/logic/danmaku ./integration -v)

tests/api/run-all.sh

(cd frontend && npm ci && npx playwright install chromium)
(cd frontend && npm run build && npm run test:e2e)
```

### 7.3 剩余风险

- 当前浏览器自动化仅覆盖 Chromium，尚不能证明其他浏览器兼容性。
- 尚未完成正式性能、容量、长稳、安全渗透及云原生故障实验。
- 部分报告来自不同成员机器，Go、Node.js 和数据库小版本存在差异；最终验收应以统一 CI 和固定演示环境再执行一次全量测试。
- E2E 和媒体测试依赖端口、MySQL、FFmpeg、SRS 及测试文件目录，环境配置错误可能造成非业务失败。

### 7.4 结论

截至 2026-08-29，DanmakuStream 单体版本在现有功能测试范围内满足进入中期验收和后续微服务拆分阶段的条件。建议在单体版本冻结前，以 `monolith-start` 对应版本或最终冻结提交在统一环境再执行一次 `go test`、全部 API 套件和统一 Playwright E2E，并保存该次 CI artifact，作为单体与微服务性能及回归对比的最终基线。
